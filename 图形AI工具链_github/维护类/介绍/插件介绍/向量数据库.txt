知识库系统技术实现概要
1. 多级索引结构
• 基于数据量自动分层的层级索引（Level 1~N）
• 每层数据量阈值：1000条(因边界条件处理模糊导致前两千条数据被分到了一个簇里)
• 层级公式：floor(log(总数据量, 1000))
2. 向量检索技术
• 向量维度：8192维
• 相似度算法：
  • 余弦相似度（核心相似度方法）
  • 向量归一化处理
• 张量精度：torch.float16
• 混合检索策略：
  • 粗筛选：通过索引层级快速筛选候选簇
  • 细匹配：底层细粒度相似度排序
3. 聚类算法
• K-means聚类（通过sklearn实现，可选）
• 备选方案：简易等分聚类（无sklearn时）
• 聚类特征：对原始向量进行均值池化
• 自动计算簇数：数据量 // 1000
4. 数据库优化
• SQLite + WAL模式
• 索引缓存机制
• 批量事务处理
• 强制刷盘保证数据持久性
5. 查询流程
用户查询 → 文本向量化 → 层级索引检索 → 候选簇筛选 → 细粒度相似度排序 → TopN返回
6. 核心创新点
• 统一的_细粒度相似度匹配底层方法
• 动态层级扩展机制
• 索引缓存加速检索
• 混合检索策略（粗筛+精排）
7. 技术栈
• 模型：Qwen-7B-INT4（向量生成）
• 数据库：SQLite + 自定义索引
• 向量计算：PyTorch + NumPy
• 可选聚类：scikit-learn
系统实现了从海量数据中快速检索相关记忆的能力，通过多级索引平衡了召回率与检索速度。

注意一些细节:
1.为了提升命中率我们对此模型将不采用上下文维护,用户输入->模型反馈命令->工具反馈结果->模型整理,这两个输入给模型的过程上下文完全是独立的
  而且我们会在用户输入给模型的时候给模型自我定义,并且它输出的不满足格式,工具会报错,这会让模型重复输出直到满足格式为止
  独立对话加分情况拼接定义提示词的策略使得每一次查询速度都比较可观,并且得益于数据库架构设计,理论上来讲哪怕是32GB以下的内存也可以支持上亿条数据的查询
2.向量的压缩也是基于千问7B模型内部的压缩层实现的,如果查询内容正确,召回率较高,并且这些压缩是基于数据本身,而并不是概括后的标签
